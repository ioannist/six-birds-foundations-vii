# E2 Bounded Reflexivity Predictions

This is the pre-registered prediction artifact for the E2 toy-laboratory
probe. It is intentionally written before any E2 sweep implementation exists.
Round B should implement the sweep against this document, not redesign the
configuration after seeing results.

No experiment has been run for this artifact. All quantities below are exact
and should be represented with `fractions.Fraction` where arithmetic is
needed. This E2 Round A instance is fully deterministic: no random seed,
stochastic simulation, or hash-audited float branch is required.

## 1. Toy-Lab Configuration

### Repair-World Carrier And Audit Flags

The sweep specializes `lab/sixbirds_foundations_v/worlds/repair_world.py`.
It uses `RepairWorldState`, `RepairWorldConfig`, `AuditState`,
`AuditFlags`, `ChallengeClass`, `ChallengeProcess`, and `RepairAction`
directly. The audit tower is carried by the existing field:

```python
state.A = AuditState(instrument=instrument, flags=AuditFlags(levels))
```

where `levels` is one of:

```text
depth 1: frozenset({0})
depth 2: frozenset({0, 1})
depth 3: frozenset({0, 1, 2})
```

The sweep must use the actual carried `AuditFlags`/tower records to compute
depth, footprint, saturation, and per-level status. A copied status table is
not evidence for E2.

The Repair-World carrier items are the same small four-item fixture used by
the E1 internalization toy lab:

```text
X = {a,b,c,d}.
```

The initial quotient is:

| item | `Q0(item)` |
| --- | --- |
| `a` | `u` |
| `b` | `u` |
| `c` | `v` |
| `d` | `v` |

The challenge process has recurrence period `1` and two drifted repair
episodes:

```python
C_base = ChallengeClass("baseline")
C_ab = ChallengeClass("split_ab")
C_cd = ChallengeClass("split_cd")

challenge_process = ChallengeProcess(
    recurrence_period=1,
    default_challenge=C_base,
    drift_schedule={2: C_ab, 3: C_cd},
    binding_states=frozenset({0, 1, 2, 3, 4}),
)
```

Thus `challenge_at(t, y)` returns `baseline` at `t = 0,1`, `split_ab` at
`t = 2`, and `split_cd` at `t = 3,4`.

The registered obstruction counts are:

```text
DeltaCount(Q0, C_ab) = 1   -- challenged pair {a,b}
DeltaCount(Q1, C_ab) = 0   -- after R_ab
DeltaCount(Q1, C_cd) = 1   -- challenged pair {c,d}
DeltaCount(Q2, C_cd) = 0   -- after R_cd
```

The two E1-style endogenous repair occurrences are:

```text
rho_2 installs R_ab and produces Q1 = Q0 vee R_ab.
rho_3 installs R_cd and produces Q2 = Q1 vee R_cd.
```

Both `rho_2` and `rho_3` are registered as genuine
`AuditedRepairTrigger` witnesses: each is in `H.repairAuditEntries`, satisfies
`EndogenousRepairOccurrence`, is generated by `S.R_S`, passes
`ESystem.RepairStep`, and passes `CorePromotionGatesPass`.

### Carried Audit Levels

The tower has at most three carried audit levels. Level indices and tags are:

| level index | level tag | lower-stack target |
| ---: | ---: | --- |
| `0` | `10` | `[]` |
| `1` | `20` | `[0]` |
| `2` | `30` | `[0,1]` |

The `FreshRotatingLevelBridge` prediction is:

```text
level 1 is a fresh extension of depth 1:
  20 > 10 and lowerStackTarget = [0]

level 2 is a fresh extension of depth 2:
  30 > 10, 30 > 20 and lowerStackTarget = [0,1]
```

Every nonzero level has positive footprint. The lower-stack audit fields are

actual carried level record.

### Capacity Measure

The main capacity fixture uses one carrier state `z_cap` with:

```text
cap(z_cap) = 8.
```

The carrier record universe is the following eight record identifiers:

```text
U(z_cap) =
  { ir0, vis0,
    ir1, thr1, led1,
    ir2, chk2, aud2 }.
```

The per-level record sets are disjoint subsets of `U(z_cap)`:

| level | record set | footprint |
| ---: | --- | ---: |
| `0` | `{ir0, vis0}` | `2` |
| `1` | `{ir1, thr1, led1}` | `3` |
| `2` | `{ir2, chk2, aud2}` | `3` |

The record identifiers are deliberately typed by source category:

```text
ir*  = carried instrument record
vis* = visibility record
thr* = threshold record
chk* = check-rule record
led* = carried ledger entry
aud* = carried audit record
```

This covers the five categories in E2's `countsOnlyCarriedRecords` clause:
instrument record, visibility records, threshold records, check-rule records,
and carried ledger/audit entries used by the level.

The registered tower footprints are hand-computed:

| depth `n` | active levels | `TowerFootprint` | `CapacityAdmissible` at cap `8` |
| ---: | --- | ---: | --- |
| `0` | `{}` | `0` | yes |
| `1` | `{0}` | `2` | yes |
| `2` | `{0,1}` | `2 + 3 = 5` | yes |
| `3` | `{0,1,2}` | `2 + 3 + 3 = 8` | yes |
| attempted `4` | `{0,1,2,3}` with next footprint `2` | `10` | no |

Therefore depth `3` is exactly saturated for this carrier: it currently fits,
but any positive-footprint next level of footprint at least `2` would give
`8 + 2 = 10 > 8`.

## 3. Diminishing Returns Prediction

The audit-depth tradeoff is evaluated over depths `0,1,2,3` at fixed
`cap(z_cap) = 8`. Depth `0` means no carried audit tower; depths `1,2,3` use
the footprints above.

The registered repair-error rate table is:

| depth | error rate |
| ---: | ---: |
| `0` | `3/4` |
| `1` | `1/2` |
| `2` | `1/3` |
| `3` | `1/4` |

The marginal error reductions are:

```text
depth 0 -> 1: 3/4 - 1/2 = 1/4
depth 1 -> 2: 1/2 - 1/3 = 1/6
depth 2 -> 3: 1/3 - 1/4 = 1/12
```

so the audit benefit is diminishing.

The registered audit capacity cost is:

```text
AuditCost(depth) = TowerFootprint(depth) / 24.
```

Thus:

| depth | footprint | audit cost | error rate | total loss `J = error + cost` |
| ---: | ---: | ---: | ---: | ---: |
| `0` | `0` | `0` | `3/4` | `3/4 = 18/24` |
| `1` | `2` | `2/24 = 1/12` | `1/2` | `7/12 = 14/24` |
| `2` | `5` | `5/24` | `1/3` | `13/24` |
| `3` | `8` | `8/24 = 1/3` | `1/4` | `7/12 = 14/24` |

Registered prediction: the unique optimum is depth `2`, with exact total loss
`13/24`. It is nonzero and non-maximal:

```text
0 < 2 < 3.
```

This is the toy-lab version of THEOREMS.md's "audit depth behaves as a priced
good with diminishing returns" claim.

## 5. Scope Note: Actual Carried Tower vs Feasible Tower

The registered predictions are about the actual carried tower exposed by
`RepairWorldState.A.flags` and the associated carried level/status records.
They are not about an existential claim that some tower of a given depth could
fit the capacity bound.

Round B may compute a separate feasibility table, but it must not use an
existential feasible tower as the status classifier. The status rows above must
be derived from:

```text
ActualCarriedTower:
  tower slots present in state.A.flags and carried level records

not from:

ExistentialFeasibleTower:
  some capacity-admissible tower that could have existed
```

This is the E2 analogue of the E1 generator-reachability and E7
viability-kernel scope guards.

## 6. Falsification Conditions

The following outcomes falsify the corresponding registered predictions.

1. The Repair-World audit carrier is falsified if `state.A.flags` is not used
   to distinguish depths `1`, `2`, and `3`, or if status/depth rows are copied
   from this document rather than derived from carried tower records.

2. The challenge/trigger fixture is falsified if `challenge_at(t,y)` does not
   return `baseline` at `t=0,1`, `split_ab` at `t=2`, and `split_cd` at
   `t=3,4`, or if `rho_2`/`rho_3` fail the registered E1-style
   `AuditedRepairTrigger` checks.

3. Self-soundness obstruction is falsified if `claim_circular` is classified
   as `accepted`, or if the circularity control is classified as
   `active_scoped`.

4. Forced stratification is falsified if an audited repair trigger at
   non-saturated depth `1` fails to rotate to depth `2`, if a trigger at
   non-saturated depth `2` fails to rotate to depth `3`, or if any FIII
   extension reports `selfSoundnessAccepted = true`.

5. Fresh-level bridge discipline is falsified if a new level is accepted with
   a non-increasing tag, with the wrong `lowerStackTarget`, or with a
   lower-stack audit field not matching `[0,...,n-1]`.

6. Capacity arithmetic is falsified if the computed tower footprints are not
   exactly `0`, `2`, `5`, `8`, and attempted `10` at depths `0`, `1`, `2`,
   `3`, and `4`, respectively.

7. Capacity saturation is falsified if depths `1` or `2` are saturated under
   cap `8`, or if depth `3` is not saturated when the minimum next positive
   footprint is `2`.

8. The capacity-null control is falsified if the attempted depth `4` tower
   with footprint `10` is accepted as `CapacityAdmissible` under cap `8`.

9. Per-level status exactness is falsified if any status-table row has zero
   statuses or more than one status, or if any row's predicted status differs
   from the table in section 2.

10. The diminishing-returns prediction is falsified if the exact total-loss
    table is not `{18/24, 14/24, 13/24, 14/24}` for depths `{0,1,2,3}`, or if
    the unique optimum is not depth `2`.

11. The unlinked bridge control is falsified if a FIII extension for `stack_1`
    can be paired with `badNextLevel.levelIndex = 2` and still satisfy
    `CarriedRotatingExtensionRealized` as an extension from depth `1`.

12. The incomplete tower inventory control is falsified if a tower omitting a
    genuine carried level occurrence can satisfy `CompleteCarriedInstrumentTower`
    or `CompleteBoundedReflexivityStatus`.

13. The actual-tower discipline is falsified if Round B classifies status from
    an existential feasible tower rather than from the concrete carried tower
    in `state.A.flags` and the carried level/status records.

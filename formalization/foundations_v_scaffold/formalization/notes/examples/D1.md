# D1 — Repair join

**Source text:** THEOREMS.md §1.2, D1.  
**Target Lean module:** `SixBirdsFoundationsV.Definitional.RepairJoin`.  
**Grounding:** Foundations IV Theorem 5.2 (`thm:F2`) supplies the source-refinement repair basis. The join symbol and binary operation are Foundations-V-local.

## 1. Setup

Let `X` be a finite carrier. A quotient on `X` is presented in the house style as a map

```text
q : X -> A
```

for some codomain `A`, with semantic content given by its fiber relation

```text
x ~q x'  iff  q x = q x'.
```

Two quotient presentations `q : X -> A` and `q' : X -> A'` represent the same quotient when they have the same fiber relation on `X`. The codomain is presentation data; the quotient is the induced partition/fiber relation.

For two quotient maps on the same carrier,

```text
q : X -> A
r : X -> B
```

say that `q` refines `r`, written here as `q <= r` in the fineness order, when equality in `q` implies equality in `r`:

```text
q <= r  iff  forall x x', q x = q x' -> r x = r x'.
```

Equivalently, `r` factors through `q` on the image of `q`. Thus “finer” means “has no larger fibers.” This orientation matches the source-refinement move: replacing `q` by a finer quotient separates distinctions that `q` had collapsed.

The common-carrier hypothesis is essential: `q` and `r` must both read the same underlying `X`. D1 is not a join of unrelated codomains.

## 2. Definition

For quotient presentations `q : X -> A` and `r : X -> B`, define their repair join

```text
q vee r : X -> ImageOf (fun x => (q x, r x))
```

by

```text
(q vee r)(x) = image point represented by (q x, r x).
```

Equivalently, one may use the raw product map

```text
x |-> (q x, r x) : X -> A x B
```

because the unused product points do not affect the fiber relation. The image codomain is the cleaner later-Lean target because it avoids pretending that all pairs in `A x B` are reachable.

The induced equivalence relation is

```text
x ~(q vee r) x'  iff  q x = q x' and r x = r x'.
```

This is the common refinement of the two partitions. It is well-defined as a quotient, independent of the particular codomain presentations of `q` and `r`: replacing either map by a fiber-equivalent presentation leaves the displayed conjunction unchanged.

D1’s source-refinement operation by a repair package `r` is therefore

```text
q |-> q vee r.
```

The definition is usable only with the following universal property:

1. `q vee r` refines `q`.
2. `q vee r` refines `r`.
3. If `s : X -> C` refines both `q` and `r`, then `s` refines `q vee r`.

Under the refinement order defined in Setup, where finer quotients are smaller (`<=`) and coarser quotients are larger, this is the standard order-theoretic meet / greatest-lower-bound property, not the join / least-upper-bound property. The symbol `vee` and the name “join” are preserved from THEOREMS.md’s established D1 wording: `Q vee R` is the common refinement. Future readers and Lean code should therefore treat `vee` as the project’s name for this common-refinement operation, while recognizing that it is meet-shaped under the stated order.

In factorization form, item 3 says that every common refinement `s` admits a unique map on the image of `s`

```text
bar : ImageOf s -> ImageOf (fun x => (q x, r x))
```

with

```text
bar (sImage x) = (q vee r)(x).
```

This makes `q vee r` the coarsest quotient refining both `q` and `r`, unique up to fiber-equivalence of quotient presentations.

Minimal later-Lean lemmas:

- `join_refines_left : q vee r <= q`
- `join_refines_right : q vee r <= r`
- `vee_greatest_lower_bound : s <= q -> s <= r -> s <= q vee r`
- `join_well_defined` under fiber-equivalent replacement of `q` and `r`
- `join_idem : q vee q` is fiber-equivalent to `q`
- `join_comm : q vee r` is fiber-equivalent to `r vee q`
- `join_assoc : (q vee r) vee s` is fiber-equivalent to `q vee (r vee s)`

The last three are not extra mathematical claims; they are the lattice facts needed to make the notation stable downstream.

## 3. Proof Spine

The construction is the product/image map. On any carrier, and therefore on a finite carrier, equality in the product is componentwise equality:

```text
(q x, r x) = (q x', r x')  iff  q x = q x' and r x = r x'.
```

This immediately proves the fiber characterization of `q vee r`.

Left and right refinement follow by projection. If `(q vee r)(x) = (q vee r)(x')`, then product equality gives both `q x = q x'` and `r x = r x'`.

For the greatest-lower-bound property, let `s : X -> C` refine both `q` and `r`. If `s x = s x'`, then the refinement hypotheses give `q x = q x'` and `r x = r x'`, hence `(q vee r)(x) = (q vee r)(x')`. Thus `s` refines `q vee r`. The descended map from `ImageOf s` to the image of the product is defined by choosing any representative `x` of a point in `ImageOf s` and sending it to `(q vee r)(x)`; the preceding sentence proves this is independent of representative.

Well-definedness under presentation change is also immediate from the fiber characterization. If `q` and `q'` have the same fibers, and `r` and `r'` have the same fibers, then

```text
q x = q x' and r x = r x'
```

holds exactly when

```text
q' x = q' x' and r' x = r' x'.
```

So the two joins have the same fibers even if their codomains are different.

Idempotence: `q vee q` has fiber relation `q x = q x' and q x = q x'`, which is the same as `q x = q x'`.

Commutativity: `q vee r` and `r vee q` have fiber relations `q x = q x' and r x = r x'` and `r x = r x' and q x = q x'`, which are logically equivalent.

Associativity: both `(q vee r) vee s` and `q vee (r vee s)` have fiber relation

```text
q x = q x' and r x = r x' and s x = s x'.
```

Thus associativity holds up to fiber-equivalence, which is the correct equality notion for quotient presentations.

No extra hypothesis beyond common carrier and equality on codomains is needed for the basic join facts. Finiteness is retained because Foundations V’s later carriers and the vendored Lean apparatus are finite-map oriented, not because the product construction itself fails on infinite carriers.

## 4. Case Enumeration

- **Idempotent case:** `q vee q` is the same quotient as `q` up to fiber-equivalence. A repair package already present in the source does not add distinctions.
- **One quotient already refines the other:** if `q <= r`, then `q vee r` is fiber-equivalent to `q`. Dually, if `r <= q`, then `q vee r` is fiber-equivalent to `r`.
- **Trivial coarse quotient:** if `q` is the constant quotient, then `q vee r` is fiber-equivalent to `r`.
- **Discrete quotient:** if `q` separates every point of `X`, then `q vee r` is fiber-equivalent to `q`.
- **Empty carrier:** if `X` is empty, every quotient map has empty image and all quotient presentations have the same empty fiber relation. The universal property is vacuous but still valid.
- **Presentation mismatch:** maps `q : X -> A` and `q' : X -> A'` with isomorphic or non-isomorphic codomains may still represent the same quotient. D1 compares them only by fibers, so the join is invariant under this mismatch.

## 5. Interaction Status

D1 does not duplicate Foundations IV F2. F2 states the descent-repair normal form and identifies source refinement as one canonical repair when a composite readout fails to descend. D1 supplies the missing Foundations-V-local binary operation for the source-refinement side: given an existing quotient `q` and a repair package/readout `r`, the source-side repaired quotient is `q vee r`.

D1 is also adjacent to F7 and F10 but not reducible to either:

- **F7 Sufficiency Closure** asks whether a declared family of future probes factors through a current quotient. D1 gives the operation that can refine a quotient by adding a probe/readout, but D1 does not declare the probe family or prove sufficiency for any downstream family.
- **F10 Quotientality** characterizes a coarsest quotient carrying declared observations. D1 is a binary join of already-given quotient presentations. In cases where `r` is an observation signature, `q vee r` may instantiate an F10-style coarsest quotient for the combined observations, but that is an audited map between positions, not a claim that D1 is “just F10.”

Under the anti-reductionism discipline, D1’s role is map-and-audit infrastructure: it records how a repair package changes the source quotient on a common carrier. Whether a downstream use is an imported source, a local repair, or a recognition-mode bridge remains a D3 source-of-truth classification question.

## 6. Nonclaims

- D1 does not assert that a repair package `r` is available, justified, canonical, or externally grounded.
- D1 does not assert that applying `q |-> q vee r` solves any descent problem by itself; that requires the F2-style obstruction and repair hypotheses for the specific map/readout at issue.
- D1 does not choose between source refinement and target coarsening. It only formalizes the source-refinement operation.
- D1 does not identify quotient codomains as canonical objects. All uniqueness is up to fiber-equivalence on the carrier.
- D1 does not assert that `vee` satisfies Lean/Mathlib-style `SemilatticeSup` or supremum laws under the finer-`<=`-coarser order. Under that order it is order-theoretically a meet, named `vee`/“join” only because that is THEOREMS.md’s established term for this common-refinement operation.
- D1 does not assert that the joint quotient it constructs is admissible as joint access. It constructs an unrestricted product/common-refinement quotient that can witness the formal product shape, but FIV F37's obstruction is to membership in the relevant admissible access class, not to bare product factorization.
- D1 does not assert a general theorem about infinite carriers in Foundations V. The construction extends formally, but this project’s intended carriers and Lean substrate are finite-map based.
- D1 does not create a new biological or life-sciences claim, and no such content is used in this definition.

# D6 - Exposure Cost And Probe Economy

**Source text:** THEOREMS.md §1.2, D6.  
**Target Lean module:** `SixBirdsFoundationsV.Definitional.ProbeEconomy`.  
**Grounding:** Hiddenness Definition `def:visibility-coupling` supplies the binary exposure predicate; D2 supplies the Xi residual, chain rule, and same-family saturation apparatus; D3 supplies carried records; D4 supplies the E-system carrier, fixed record policies, and carried ledger `Lambda_S`; E6 is the first direct consumer, using D6 probe weights and exposure budget.

## 1. Setup

D6 turns exposure from a theorist-declared yes/no predicate into a carried, priced, controlled selection process inside a D4 E-system.

### Hiddenness exposure

Hiddenness Definition `def:visibility-coupling` defines

```text
Exposure(Lift, Substrate)
```

as a proposition. It holds exactly when there exist:

```text
O                         observable codomain
phi_Q : HistorySpace -> O declared polynomial-time current observable
f : S -> O                polynomial-time function of the lift state
```

such that `f` is non-constant on the realized image of the internal-state readout

```text
LiftState : HistorySpace -> S
```

and

```text
phi_Q(h) = f(LiftState(h))
```

for every history `h`. The Hiddenness paper explicitly treats exposure as binary: once the value of `Exposure(Lift, Substrate)` is fixed, the dissolution/preservation branch is fixed. There is no price, exposure budget, active-probe ledger, or system-chosen acquisition move in that definition.

For D6, this means:

- **binary:** Hiddenness exposure is a yes/no proposition;
- **free:** the definition contains no cost, budget, or scarcity term;
- **exogenous:** the current observable `phi_Q` is declared by the framework, not selected, paid for, retired, or reweighted by the system as a carried state variable.

D6 does not redefine `Exposure`. It defines the probe economy that determines which observables are actively purchased and carried before a current observable can be credited as system-controlled exposure.

### D4 carrier, carried active family, and ledger

Let

```text
S : ESystem ...
T := S.T
```

be a D4 E-system. The probe economy lives on the same carrier and audit surface as D4. The active probe family at time `t`,

```text
L_t subset ProbeCatalog
```

is a D3 carried record over `T.Z`, checked through a fixed D4 `CarriedRecordPolicy`. Because `L_t` is indexed by time, the Lean target should prefer an occurrence-level predicate such as

```text
ActiveFamilyCarriedAt(S, economy, L_t, n0, sourceTag, generatedByS, inScope)
```

using `CarriedRecordAt`, not a fresh existential over arbitrary source fields. The exact representation of `L_t` should expose:

```text
support(L_t)        finite active probe support
weight(L_t, p)      exposure weight/intensity for active probe p
asXiFamily(L_t)     optional matrix/native-family representation for operator labs
```

This is required by E6, which uses a weighted active family `L_w` and the Xi residual `Xi_C(D | L_w)`.

Costs and the exposure budget live in D4 `Lambda_S`. Concretely, the economy should include carried ledger entries for:

```text
costPerExposure(p)
B_exp
spentExposure
budget status / residual slack
```

D6 should reuse `S.Lambda_S : CarriedLedger T LedgerEntry`, with certified predicates saying which ledger entries encode exposure costs and budgets. It should not introduce a parallel budget ledger.

### Probe catalog

A probe catalog is a declared finite family:

```text
ProbeCatalog : finite list/set of candidate probes
```

with a certified catalog-completeness predicate. A probe can be inactive but catalog-declared. It becomes active only through an acquisition move, not by silently treating zero exposure weight as "already active."

The finite catalog is part of the definition because D6 is not a free quantification over every observable the theorist can name. A host must declare the candidate probes and their cost/budget hooks before later laws can optimize over them.

### Same-family saturation and strict extension

The strictness test for acquisition is not new Foundations-V vocabulary. The vendored Xi module `Xi.StrictExtension` proves:

```text
sameFamilySaturation
```

If a candidate extension `M` factors through the current native family `L`,

```text
M = B * L
```

and the conditional currency term is zero, then the extended residual equals the original residual. D2 already uses this as

```text
predictiveSurplusXi_same_family_saturation
```

to show that same-family additions do not change the Xi-trace surplus.

D6 should therefore have two levels:

1. **Abstract probe-economy level.**

   ```text
   SameFamilySaturated(L_t, M) : Prop
   AcquisitionStrict(L_t, M) := not SameFamilySaturated(L_t, M)
   ```

   or an equivalent certified strict-extension predicate. This is the core definition-level gate. A lawful acquisition requires the strictness certificate; it cannot treat strictness as commentary.

2. **Xi operator-lab instantiation.**

   When `L_t` and `M` are represented by matrices, `SameFamilySaturated(L_t, M)` is witnessed by the Xi factorization/zero-conditional-currency hypotheses used by `sameFamilySaturation`. In that host, a saturated `M` is exactly a fake extension for D6 acquisition: it adds no new residual-discharge capacity under the declared Xi laboratory.

D6 does not prove a bridge from every abstract probe catalog to the Xi matrix representation. This mirrors D2: the abstract predicate is the definition interface, while Xi supplies a concrete laboratory form for E6.

## 2. Definition

A **probe economy** for an E-system `S` consists of the following data and certificates.

### 2.1 Catalog and active-family state

```text
Probe                         probe type
ProbeCatalog : finite family Probe
CompleteProbeCatalog : Prop
ActiveFamily                  active support + weights + optional host data
activeFamilyPolicy            CarriedRecordPolicy S.T ActiveFamily
```

The carried active family at time/read point `n0` is:

```text
CarriedRecordAt activeFamilyPolicy L_t n0 sourceTag generatedByS inScope
```

where D3 `CarriedSource` must hold through that `CarriedRecordAt` proof. Thus `L_t` is not a theorist-side selected list; it is a state coordinate carried by the system.

D6 also requires the active support itself to be catalog-valid:

```text
ActiveSupportInCatalog(economy, L_t) :=
  forall p, p in support(L_t) -> p in ProbeCatalog

LawfulActiveFamilyAt(economy, L_t, n0, sourceTag, generatedByS, inScope) :=
  ActiveSupportInCatalog(economy, L_t)
  and CarriedRecordAt activeFamilyPolicy L_t n0 sourceTag generatedByS inScope
```

The lawful move predicates require `LawfulActiveFamilyAt` for both the pre-move
active family and the post-move active family. This is load-bearing: an
allocation theorem saying "no new probe was added" is only meaningful when the
pre-state support was already catalog-valid and carried.

The active support convention is load-bearing:

```text
p in support(L_t)  iff  p is active.
```

Allocation may change weights only on this support. A catalog-declared probe with zero current exposure is not active merely because it appears in `ProbeCatalog`.

### 2.2 Ledger and budget data

The economy includes carried ledger hooks into `S.Lambda_S`:

```text
ExposureCostEntry(p, c)        c is the carried per-unit exposure cost of p
ExposureBudgetEntry(B_exp)     B_exp is the carried exposure budget
ExposureSpendEntry(spend)      current spent exposure budget
BudgetAdmissible(move)         the move respects the carried budget ledger
```

These are certified predicates over D4 ledger entries, not a new ledger. A lawful D6 move must point to the relevant carried ledger entries and satisfy the budget admissibility predicate.

D6 can allow a host to declare zero cost only if that zero cost is itself carried in the ledger. Later E6 supplies the no-zero-cost-credit discipline for attention claims; D6 only prevents undeclared free exposure.

### 2.3 Moves

D6 has three move kinds.

#### Allocation

Allocation changes exposure weights within the current active support:

```text
AllocationMove(L_t, L_t')
```

requires:

```text
L_t is a lawful active family at the pre-move read point
support(L_t') = support(L_t)
weights changed only for probes in support(L_t)
budget ledger entries exist for the affected probes
BudgetAdmissible(allocation)
L_t' is a lawful active family at the post-move read point
```

Allocation is not allowed to add a new positive-support probe. If a probe moves from inactive/zero support to positive active support, the move is acquisition, not allocation.

#### Acquisition

Acquisition adds a catalog probe or family `M` to the active family:

```text
AcquisitionMove(L_t, M, L_t')
```

requires:

```text
L_t is a lawful active family at the pre-move read point
M in ProbeCatalog
M notin support(L_t)
support(L_t') = support(L_t) union {M}    -- or the host's finite-family analogue
AcquisitionStrict(L_t, M)                 -- not same-family-saturated
budget ledger entries exist for M
BudgetAdmissible(acquisition)
L_t' is a lawful active family at the post-move read point
```

The strictness requirement is mandatory. If `SameFamilySaturated(L_t, M)` holds, then acquisition is not lawful as a strict exposure extension, even if `M` is syntactically new or mathematically convenient.

#### Retirement

Retirement removes an active probe from the active support:

```text
RetirementMove(L_t, M, L_t')
```

requires:

```text
L_t is a lawful active family at the pre-move read point
M in support(L_t)
support(L_t') = support(L_t) \ {M}        -- or the host's finite-family analogue
M inactive in L_t' = absent from post-support
numeric zero weight is optional host-level invariant
ledger/status update records the retirement
BudgetAdmissible(retirement)
L_t' is a lawful active family at the post-move read point
```

Retirement does not need a same-family strictness test symmetric to acquisition. It does not claim to add new exposure information or discharge residual content; it removes active exposure capacity and updates the ledger/status state. A no-op "retirement" of an already inactive probe should not count as a retirement move; it is either invalid or just a ledger/status no-op.

### 2.4 Controlled, priced, carried exposure

An exposure predicate becomes D6-controlled only when the observable family used to witness it is generated from the carried active family and paid for by the carried ledger:

```text
ExposureWitnessUses(L_t, phi_Q)
```

and the move history that produced `L_t` consists of lawful allocation/acquisition/retirement moves. Hiddenness may still say `Exposure(Lift, Substrate)` holds for a theorist-declared `phi_Q`; D6 says when that exposure channel is endogenous, budgeted, and carried by `S`.

Minimal later-Lean declarations should include:

- `ProbeCatalog` / `CompleteProbeCatalog`;
- `ActiveFamily` with finite active support and weights;
- `ActiveFamilyCarriedAt` using D4 `CarriedRecordAt`;
- `ActiveSupportInCatalog` and `LawfulActiveFamilyAt`;
- `SameFamilySaturated` and `AcquisitionStrict`;
- `ProbeMove` with allocation/acquisition/retirement cases;
- `LawfulAllocation`, `LawfulAcquisition`, and `LawfulRetirement`;
- a `ProbeEconomy` structure bundling catalog, active-family policy, ledger hooks, strictness, and budget-admissibility predicates;
- optional Xi instantiation lemmas reusing D2/Xi same-family saturation.

## 3. Proof Spine

D6 is a definition. The proof work is well-definedness of the probe-economy interface and non-vacuity of the move guards.

### What is straightforward

Given D3 and D4:

- `L_t` can be made carried by reusing `CarriedRecordAt activeFamilyPolicy ...`, and can be made lawful as an active family by conjoining that carriedness with `ActiveSupportInCatalog`.
- Every lawful allocation, acquisition, and retirement now requires `LawfulActiveFamilyAt` for the pre-state and post-state. This blocks malformed pre-states, such as a support list containing a non-catalog probe or an active family that was never carried, from being used as the starting point of a lawful move.
- Exposure cost and budget can be tied to `S.Lambda_S` by requiring ledger entries and `BudgetAdmissible` predicates over the D4 carried ledger.
- Finite support and support-preserving allocation are ordinary finite-list/set checks once the host picks a concrete representation.
- Acquisition non-vacuity is direct: `LawfulAcquisition` contains `AcquisitionStrict(L_t, M)`, so a same-family-saturated `M` cannot be accepted as a strict acquisition.

In the Xi matrix host, the vendored theorem

```text
sameFamilySaturation
```

says that a factor-through extension with zero conditional currency leaves the adequacy residual unchanged. Therefore a host that defines

```text
SameFamilySaturated(L_t, M)
```

from those Xi hypotheses can prove that a saturated `M` fails `AcquisitionStrict`. This is exactly the strictness check THEOREMS.md names.

The allocation/acquisition boundary is also checkable. Because allocation requires

```text
support(L_t') = support(L_t),
```

it cannot smuggle a new active probe by assigning positive weight to an inactive catalog member. Moving a probe from inactive to active changes support and must be handled by acquisition, where the same-family strictness and budget gates apply.

Retirement is simpler. A lawful retirement requires `M` to be active before the move and inactive after the move. Since retirement removes exposure capacity rather than claiming a strict new extension, it has no same-family strictness obligation. The non-vacuity check is the active-before/absent-after condition plus carried ledger/status update.

### What is deferred

D6 does not prove KKT optimality, dual variables, salience, slack collapse, or marginal-discharge ratios. Those are E6 obligations.

D6 also does not derive the honesty of `CompleteProbeCatalog`, budget admissibility, cost values, or the host's `SameFamilySaturated` predicate. Those are certified inputs, as in D3/D4/D5. Later toy-laboratory and E-law units must instantiate them concretely.

D6 does not additionally require `p notin support(L_t) -> weight(L_t,p) = 0`.
The definition remains safe only if later consumers use support membership, not
positive weight alone, as the definition of active exposure. If a later E-law or
host laboratory reads weights outside support as active exposure, that unit must
add a zero-off-support well-formedness invariant.

D6 does not prove that acquisition improves predictive surplus. It only rules out the recognized fake-extension case. E6 must combine D6 with D2/Xi chain-rule discharge and budget binding to prove attention allocation laws.

## 4. Case Enumeration

- **Allocation within active support:** the pre-state `L_t` is catalog-valid and carried, weights on already-active probes change, support is unchanged, costs are charged to `Lambda_S`, and the post-move `L_t'` is catalog-valid and carried. This is a lawful allocation candidate.
- **Malformed pre-active family:** `L_t` contains a non-catalog probe, or `L_t` lacks a carried read-off proof at its declared pre-move occurrence. No D6 move can be lawful from this pre-state, even if the post-state is well formed.
- **Zero-to-positive dormant probe:** a catalog probe with zero or inactive support is given positive exposure. This changes support, so it is acquisition, not allocation. It must pass strictness and budget checks.
- **Same-family fake acquisition:** `M` is syntactically named as new but factors through `L_t` in the Xi sense and the conditional term is zero. Same-family saturation holds, so `AcquisitionStrict(L_t, M)` fails.
- **Non-catalog probe:** `M` is not in `ProbeCatalog`. Acquisition fails even if a theorist can describe an observable.
- **Over-budget exposure:** allocation or acquisition would exceed the carried exposure budget or lacks the required budget ledger entries. The move is not lawful under D6.
- **Retirement of active probe:** a catalog-valid, carried pre-state contains `M`; `M` is removed, its weight/status is updated in the ledger, the probe-specific retirement record is present, and the post-move active family is catalog-valid and carried. No same-family strictness test is needed.
- **Retirement of absent probe:** `M` is already inactive. This is not a lawful retirement; it is either invalid or a no-op status update.
- **Hiddenness exposure without D6 economy:** `Exposure(Lift, Substrate)` holds for a declared current observable, but the observable is not generated from a carried active family or paid for by `Lambda_S`. Hiddenness exposure may be true, but D6-controlled exposure is absent.
- **Carried budget with no active probes:** the system may carry an exposure budget while `L_t` is empty. D6 is satisfied as infrastructure, but no attention or discharge claim follows until E6 supplies binding budget and allocation hypotheses.
- **Zero-cost declared probe:** a host may declare zero cost in the carried ledger, but no probe may be credited as purchased by an undeclared free channel. E6's no-zero-cost-credit and slack-collapse obligations decide whether such a probe supports an attention claim.

## 5. Interaction Status

- **Hiddenness exposure:** D6 does not redefine `Exposure(Lift, Substrate)`. It transforms the source of the current observable from a free, exogenous declaration into a carried, priced active-family process. Hiddenness remains the binary predicate; D6 supplies the controlled probe economy around it.
- **D2 predictive surplus and Xi:** D6's acquisition strictness is grounded in the same Xi strict-extension/same-family saturation apparatus D2 already mechanizes. D6 supplies the active weighted family `L_w` and probe budget surface that E6 later feeds into `Xi_C(D | L_w)` and the chain rule.
- **D3 carried records:** the active family `L_t` is a D3 carried record over the D4 carrier. D6 should use `CarriedRecordAt` through a fixed `activeFamilyPolicy`, not a new carriedness predicate.
- **D4 E-system and ledger:** costs, budgets, spending, and statused residuals live in `S.Lambda_S`, D4's carried ledger. D6 does not create a second accounting channel.
- **D1 repair/refinement:** adding a probe can induce a current-quotient refinement in later laws, and D1 supplies the lawful quotient-refinement operation. D6 itself is about probe support, weights, costs, and strict acquisition; it does not assert that a probe acquisition is a D1 repair join or that it improves a quotient.
- **D5 closed-loop scope:** D6 does not itself assert closed-loop repair history. If a probe acquisition is later used as a repair-typed audit entry, D5 decides whether that occurrence is closed-loop carried rather than theorist-supplied.
- **E6 Attention Law:** E6 is the primary consumer. It assumes a probe economy with `B_exp` in `Lambda_S`, weights over `L_t`, and Xi-chain-rule discharge. D6 is deliberately shaped so E6 can state KKT allocation, slack collapse, and salience without retrofitting the definition.

Under the anti-reductionism discipline, D6 is not "just" Hiddenness plus prices, nor "just" D2 Xi residuals. It is the governance object that records which observables are in the system's active, paid-for, carried probe family.

## 6. Nonclaims

- D6 does not prove `Exposure(Lift, Substrate)` holds or fails for any particular Hiddenness instance.
- D6 does not compute optimal attention weights, KKT multipliers, salience directions, or slack collapse. Those are E6 obligations.
- D6 does not assert that every lawful acquisition improves predictive surplus; it only excludes same-family-saturated fake acquisitions as strict extensions.
- D6 does not define a universal span relation independent of host data. The abstract strictness predicate must be instantiated, and the Xi matrix route is the current concrete instantiation.
- D6 does not prove a bridge between an abstract probe catalog and an Xi matrix family unless a host supplies one.
- D6 does not prove `CompleteProbeCatalog`, budget admissibility, or cost-ledger honesty. These are certified inputs.
- D6 does not allow allocation to add active support. Zero-to-positive activation is acquisition and must pass acquisition gates.
- D6 does not define off-support weights as automatically zero. Later consumers must continue to treat support membership, not positive weight alone, as the definition of active exposure unless they add an explicit zero-off-support invariant.
- D6 does not require a same-family strictness test for retirement. Retirement is a carried removal/status update, not a strict extension claim.
- D6 does not make a theorist-declared observable false or useless. It only prevents that observable from being counted as controlled, priced, carried exposure unless the D6 economy supports it.
- D6 does not introduce biological or life-sciences content.

# E10. Cognitive Demarcation Law

This is the six-field normal-form draft for E10, the Cognitive Demarcation
Law, with Corollaries E10.1 and E10.2 landed in the same unit.  The source
entry is `THEOREMS.md:293-317`, in Cluster B ("Laws of Priced Access";
heading at `THEOREMS.md:203`).  The intended Lean target is
`lean/SixBirdsFoundationsV/Laws/E10CognitiveDemarcation.lean`.

E10 is a single-`ESystem` law.  It demarcates which internal packages count
as cognitive by requiring repair, certified top-down difference-making, and
carried provenance.  E10.1 specializes the same apparatus to intention as
audited action-support restriction before outcome.  E10.2 specializes it to
goal as route-substitution-invariant target-quotient selection.  All three
belong in this landing: both corollaries reuse E10's carried package,
Delta-repair, and certified top-down-channel gating spine, and neither
requires a separate substrate comparable to the deferred E7.1/E12.1
corollaries.

## 1. Setup

### Imports and grounding

Lean should import the single-system D3/D4 surface, E1-style Delta
vocabulary, and the vendored Foundations III top-down-channel apparatus
directly:

```lean
import SixBirdsFoundationsV.Definitional.ESystem
import SixBirdsFoundationsV.Laws.E1Internalization
import SixBirdsIII.TopDownChannel
```

The FIII dependency is direct, not through E11.  E4 already established the
precedent for direct use of `SixBirdsIII.TopDownChannel` in a law that is not
itself E11 (`E4RepairCompilation.lean` imports it and owns a carried
`TopDownChannelRecord`; see the interaction row at
`interaction_matrix.md:149`).  E11 also imports the same module directly
(`E11InstitutionalRewrite.lean:1-2`) and builds
`InstitutionalIntervention`/`MatchedInstitutionalComparison` on top of it
(`E11InstitutionalRewrite.lean:64-166`), but E10's subject is a package
inside one E-system, not upper/lower institutional layer rewriting.  E10
therefore reuses FIII directly and records the E11 planning/execution bridge
as a forward compatibility question, not a prerequisite.

FIV F25/F31 are certified host input for causality/counterfactual
discipline, not locally mechanized.  The inventory records F25 at
`imported_foundations.yml:227-233` and F31 at
`imported_foundations.yml:251-257`.  The Agents paper's
enablement/causation and schedule-trap null are also certified host input
(`imported_foundations.yml:292-303`, `:460-468`).  F19-style persistence for
E10.2 is treated the same way E3/E5/E7/E12 treated F19: as certified host
input rather than a local greatest-fixed-point mechanization
(`imported_foundations.yml:135-151`).

No case predicate or falsifier may introduce a fresh taxonomy/comparator, the
same non-vacuity discipline used in E8 after the

### Carried package provenance

```lean
structure PackageCarriedProvenance
    (packagePolicy :
      CarriedRecordPolicy S.T CognitivePackageRecord)
    (formationPolicy :
      CarriedRecordPolicy S.T PackageFormationRecord)
    (invocationPolicy :
      CarriedRecordPolicy S.T PackageInvocationRecord)
    (package : CognitivePackageRecord) where
  formationRecord : PackageFormationRecord
  invocationRecord : PackageInvocationRecord
  formationLinked : formationRecord.packageRecord = package
  invocationLinked : invocationRecord.packageRecord = package
  packageCarried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt packagePolicy package n sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  formationCarried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt formationPolicy formationRecord n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  invocationCarried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt invocationPolicy invocationRecord n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  sameDeclaredClass :
    invocationRecord.challengeClass = package.declaredClass
```

This is condition (3).  A source-readable object without this provenance may
be a scaffold or externally installed structure, but it is not an E10
cognitive package.

Absence of provenance is not open-world absence over all conceivable proofs.
It is certified against a complete, claim-scoped provenance inventory:

```lean
structure CompletePackageProvenanceInventory
    (packagePolicy :
      CarriedRecordPolicy S.T CognitivePackageRecord)
    (formationPolicy :
      CarriedRecordPolicy S.T PackageFormationRecord)
    (invocationPolicy :
      CarriedRecordPolicy S.T PackageInvocationRecord)
    (package : CognitivePackageRecord) where
  declaredProvenancePairs :
    List (Prod PackageFormationRecord PackageInvocationRecord)
  completeForPackage :
    forall provenance :
      PackageCarriedProvenance S packagePolicy formationPolicy
        invocationPolicy package,
      (provenance.formationRecord, provenance.invocationRecord)
        in declaredProvenancePairs

def NoCarriedPackageProvenanceFor
    (inventory :
      CompletePackageProvenanceInventory S packagePolicy formationPolicy
        invocationPolicy package) : Prop :=
  inventory.declaredProvenancePairs = []
```

### Repair descent

`PackageRepairDescent` is the condition (1) witness.  The quotient after the
package is invoked is linked by data to the specific package through
`ctx.packageInstallsQuotient`; this is the E10 version of the E4/E5/E13
anti-pattern fix where a candidate parameter must be used by the fields that
credit it.

```lean
structure PackageRepairDescent
    (ctx : CognitiveDemarcationClassifierContext)
    (package : CognitivePackageRecord)
    (challengeClass : CognitiveChallengeClass) where
  witnessRecord : DescentWitnessRecord
  qBefore : PackageQuotientRecord
  qAfter : PackageQuotientRecord
  witnessLinked :
    witnessRecord.beforeQuotient = qBefore and
    witnessRecord.afterQuotient = qAfter and
    witnessRecord.challengeClass = challengeClass
  packageClassLinked : package.declaredClass = challengeClass
  beforeFailureNonempty : ctx.deltaNonempty qBefore challengeClass
  afterQuotientInstalledByPackage :
    ctx.packageInstallsQuotient package qBefore qAfter
  strictReduction :
    ctx.deltaStrictlyReducedBy qBefore qAfter challengeClass
```

The intended Lean implementation may expand `deltaNonempty` and
`deltaStrictlyReducedBy` into explicit `Delta` quantifiers if the local E1
API is convenient.  Either spelling must keep the
`afterQuotientInstalledByPackage` data link.

Repair absence is likewise complete-inventory-scoped:

```lean
structure CompletePackageRepairInventory
    (ctx : CognitiveDemarcationClassifierContext)
    (package : CognitivePackageRecord)
    (challengeClass : CognitiveChallengeClass) where
  declaredDescentRecords : List DescentWitnessRecord
  completeForPackage :
    forall descent : PackageRepairDescent ctx package challengeClass,
      descent.witnessRecord in declaredDescentRecords

def NoPackageRepairDescentFor
    (inventory :
      CompletePackageRepairInventory ctx package challengeClass) : Prop :=
```

### Top-down kernel difference-making

```lean
structure TopDownKernelGateCertified
    (S : ESystem FData RuleFamily ResidualFamily AuditAccessData
      InstrumentRecord LedgerEntry DefectRecord MovePayload MoveRecord
      AuditRecord)
    (ctx : CognitiveDemarcationClassifierContext)
    (interventionPolicy :
      CarriedRecordPolicy S.T PackageInterventionRecord)
    (matchedControlPolicy :
      CarriedRecordPolicy S.T MatchedControlRecord)
    (supportPolicy :
      CarriedRecordPolicy S.T KernelSupportRecord)
    (channelPolicy :
      CarriedRecordPolicy S.T SixBirdsIII.TopDownChannelRecord)
    (package : CognitivePackageRecord)
    (challengeClass : CognitiveChallengeClass) where
  channelRecord : SixBirdsIII.TopDownChannelRecord
  intervention1 : PackageInterventionRecord
  intervention2 : PackageInterventionRecord
  matchedControls : MatchedControlRecord
  support1 : KernelSupportRecord
  support2 : KernelSupportRecord
  interventionsLinked :
    intervention1.packageRecord = package and
    intervention2.packageRecord = package and
    matchedControls.interventionA = intervention1 and
    matchedControls.interventionB = intervention2
  intervention1Carried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt interventionPolicy intervention1 n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  intervention2Carried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt interventionPolicy intervention2 n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  matchedControlsCarried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt matchedControlPolicy matchedControls n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  support1Carried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt supportPolicy support1 n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  support2Carried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt supportPolicy support2 n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  channelCarried :
    exists n sourceTag generatedByS inScope,
      CarriedRecordAt channelPolicy channelRecord n
        sourceTag generatedByS inScope
        and CarriedSource sourceTag generatedByS inScope
  distinctCarriedValues :
    intervention1.packageValueId != intervention2.packageValueId
  sameChallengeClass :
    support1.challengeClass = challengeClass and
    support2.challengeClass = challengeClass and
    matchedControls.challengeClass = challengeClass
  supportsLinkedToValues :
    support1.packageRecord = package and support2.packageRecord = package
  support1ForIntervention1 :
    ctx.supportForIntervention support1 intervention1
  support2ForIntervention2 :
    ctx.supportForIntervention support2 intervention2
  channelCertifiesThisComparison :
    ctx.channelCertifiesKernelComparison channelRecord matchedControls
      support1 support2
  atLeastTwoInterventions :
    intervention1.interventionIndex != intervention2.interventionIndex
  acceptedTopDownChannel :
    SixBirdsIII.TopDownChannelAcceptedBool channelRecord = true
  notMerelyStructural :
    SixBirdsIII.TopDownChannelClaimStatus channelRecord =
      SixBirdsIII.ClaimStatus.accepted
  supportDifference :
    ctx.kernelSupportDiffers support1 support2
```

This is condition (2).  The FIII top-down channel record supplies the NC-TD
gate.  The support-difference comparator is shared through `ctx` and is not
chosen per witness.  The `supportForIntervention` fields make the comparison
specifically about the two carried intervention values, rather than an
unrelated pair of support readouts for the same package.  The channel
comparator ties that same channel record to the matched-control/support
tuple.

No accepted gate is a closed-world claim over a complete declared gate
inventory for the same package and challenge class:

```lean

      CarriedRecordPolicy S.T KernelSupportRecord)

      CarriedRecordPolicy S.T SixBirdsIII.TopDownChannelRecord)
    (package : CognitivePackageRecord)
    (challengeClass : CognitiveChallengeClass) where
  declaredAcceptedChannels : List SixBirdsIII.TopDownChannelRecord
```

Schedule traps and scaffolds have priority because they are named
falsifiers: an exogenous schedule or missing provenance must not be rescued
by a readable representation or by raw Delta improvement.

Every lower-priority case explicitly negates each higher-priority
record-independent `...EvidenceFor` predicate for the same `claimRef`.  The
status tag and record-linkage conjuncts therefore cannot discharge priority by
themselves; this is the repaired evidence-level discipline used in E5/E13/E14.

Each `...Holds` wrapper has the established three-conjunct shape:

```lean
def CognitiveHolds (...) : Prop :=
  exists record,
    CognitiveStatusOccurrenceFor S policies claimRef record and
    record.status = CognitiveStatus.cognitive and
    CognitiveCase S policies ctx claimRef record
```

The analogous wrappers are `ScheduleTrapHolds`, `ScaffoldingHolds`,
`StructuralPathOnlyHolds`, `DecodableCorrelateHolds`,
`RepairWithoutGateHolds`, `GateWithoutRepairHolds`, and `NonCognitiveHolds`.

```lean
def CompleteCognitiveStatus (...) : Prop :=

    ScheduleTrapCase S policies ctx claimRef record or
    ScaffoldingCase S policies ctx claimRef record or
    StructuralPathOnlyCase S policies ctx claimRef record or

    RepairWithoutGateCase S policies ctx claimRef record or
    GateWithoutRepairCase S policies ctx claimRef record or
    CognitiveCase S policies ctx claimRef record or
    NonCognitiveCase S policies ctx claimRef record) and
  forall record1 record2,
    CognitiveStatusOccurrenceFor S policies claimRef record1 ->
    CognitiveStatusOccurrenceFor S policies claimRef record2 ->
    record1.status = record2.status
```

```lean
        policies.evaluationPolicy theta targetClass selection
        routePersistenceInventory)

def RouteUnstableEvidenceFor policies ctx claimRef : Prop :=
  exists theta targetClass,
    claimRef = GoalClaimRef.theta theta targetClass and
    Nonempty (RouteUnstableWitness S ctx policies.routePolicy
      policies.evaluationPolicy policies.targetQuotientPolicy theta
      targetClass)

def GoalEvidenceFor policies ctx claimRef : Prop :=
  exists theta targetClass,
    claimRef = GoalClaimRef.theta theta targetClass and
    Nonempty (GoalEvidence S ctx policies.interventionPolicy
      policies.matchedControlPolicy policies.supportPolicy
      policies.channelPolicy policies.packagePolicy policies.formationPolicy
      policies.invocationPolicy policies.targetQuotientPolicy
      policies.routePolicy policies.evaluationPolicy theta targetClass)

def RewardProxyOnlyCase (...) : Prop :=
  GoalStatusOccurrenceFor ... claimRef record and
  record.status = GoalStatus.reward_proxy_only and
  exists theta targetClass,
    claimRef = GoalClaimRef.theta theta targetClass and
    exists witness : RewardProxyOnlyWitness ctx ... theta targetClass ...,
      record.rewardProxy = some witness.rewardProxy

def RouteUnstableCase (...) : Prop :=
  GoalStatusOccurrenceFor ... claimRef record and
  record.status = GoalStatus.route_unstable and
  not RewardProxyOnlyEvidenceFor S policies ctx claimRef and
  exists theta targetClass,
    claimRef = GoalClaimRef.theta theta targetClass and
    exists witness : RouteUnstableWitness ctx ... theta targetClass,
      record.targetQuotient = some witness.selection.targetQuotient and
      record.routeEvaluations = witness.routeEvaluations

def GoalCase (...) : Prop :=
  GoalStatusOccurrenceFor ... claimRef record and
  record.status = GoalStatus.goal and
  not RewardProxyOnlyEvidenceFor S policies ctx claimRef and
  not RouteUnstableEvidenceFor S policies ctx claimRef and
  exists theta targetClass,
    claimRef = GoalClaimRef.theta theta targetClass and
    exists evidence : GoalEvidence S ctx ... theta targetClass,
      record.targetQuotient =
        some evidence.selection.targetQuotient and
      record.routeEvaluations =
        evidence.routePersistence.routeEvaluations

def NotGoalCase (...) : Prop :=
  GoalStatusOccurrenceFor ... claimRef record and
  record.status = GoalStatus.not_goal and
  not RewardProxyOnlyEvidenceFor S policies ctx claimRef and
  not RouteUnstableEvidenceFor S policies ctx claimRef and
  not GoalEvidenceFor S policies ctx claimRef
```

`CompleteGoalStatus` mirrors the other completeness predicates and is scoped
by `GoalClaimRef`.

## 3. Proof Spine

1.  Unfold the carried occurrence predicate for the relevant claim.  The
    claim reference fixes the package/target, so status uniqueness is local
    to one cognitive, intention, or goal claim rather than global across the
    whole system.

2.  For E10, extract the branch-valid status record from
    `CompleteCognitiveStatus`.  Case split on the eight branch predicates.
    Each lower-priority branch carries explicit negations of every
    higher-priority record-independent `...EvidenceFor` predicate for the
    same `CognitiveClaimRef`.

3.  The positive cognitive branch is definitional once its evidence record
    supplies the three source-text conjuncts:
    `PackageRepairDescent`, `TopDownKernelGateCertified`, and
    `PackageCarriedProvenance`.

4.  The decodable-correlate and schedule-trap theorems are falsifier-shaped.
    They do not prove absence of cognition from a vague prose condition; the
    corresponding `...Holds` hypotheses already include the full carried,
    claim-linked obstruction records.

5.  E10.1 repeats the partition proof over `IntentionClaimRef`.  The
    positive branch requires `SupportRestrictionInAdvance`,
    `TargetCoherenceUnderFutureProbes`, and top-down certification.  The
    post-hoc, approximate, and target-incoherent branches are prior in the
    chain and therefore block the positive `intention` branch.

6.  E10.2 repeats the partition proof over `GoalClaimRef`.  The positive
    branch requires a target quotient plus route-substitution persistence.
    Reward scalar evidence is deliberately insufficient and has a
    higher-priority rejection branch.

7.  Direct FIII reuse enters only through
    `SixBirdsIII.TopDownChannelAcceptedBool` and
    `TopDownChannelClaimStatus`.  E10 does not import or depend on E11.
    A later combined theorem may show an E10.1 planning/execution instance
    also instantiates E11's `InstitutionalIntervention` and
    `MatchedInstitutionalComparison`, but that bridge is not needed for this
    normal form.

## 4. Case Enumeration

1.  **Clean cognitive package.**  A carried package has carried formation
    and invocation, repairs a nonempty access/action Delta failure by
    installing its own after-quotient, and has an accepted FIII top-down
    channel with at least two matched interventions and different
    access/action supports.  Status: `cognitive`.

2.  **Passive decodable register.**  The package is readable by a theorist
    and correlated with the task class, but the top-down gate is ablated and
    the support comparison is unchanged.  Status: `decodable_correlate`.

3.  **Externally installed scaffold.**  A package-like object improves the
    raw quotient but lacks carried formation/invocation provenance.  Status:
    `scaffolding`.

4.  **Schedule trap.**  A schedule variable explains the support change, and
    no accepted top-down channel is present.  Status: `schedule_trap`.

5.  **Structural path only.**  A structural downward path exists and the
    supports differ, but `TopDownChannelClaimStatus` is blocked under FIII
    NC-TD.  Status: `structural_path_only`.

6.  **Repair without difference-making.**  The package repairs a Delta
    failure, but there are not two distinct carried interventions with
    matched controls and support separation, certified by the complete
    top-down-gate inventory for this package/class.  Status:
    `repair_without_gate` unless it is decodable, in which case case 2
    applies by priority.

7.  **Top-down difference without repair.**  A support gate is certified,
    but the package does not reduce a nonempty access/action Delta failure
    for the declared challenge class, certified by the complete repair
    inventory for this package/class.  Status: `gate_without_repair`.

8.  **Wrong challenge class.**  Repair is real for `C_other`, but the claim
    is for `C_class`.  The claim-scoped occurrence predicate does not let
    the record satisfy the current claim.  Status for the current claim:
    `non_cognitive` or the appropriate obstruction branch if one is carried.

9.  **Clean intention.**  A carried `Theta` restricts the action support
    before outcome, the restricted support is a strict subset of the base
    support, future probes are declared and target-coherent, and the
    restriction is top-down certified.  Status: `intention`.

10. **Post-hoc intention.**  The action-support restriction is only recorded
    after outcome.  Status: `post_hoc_intention`.

11. **Approximate/stochastic restriction.**  A probabilistic or approximate
    support-shift is present, but exact strict support inclusion is not
    certified.  Status: `approximate_support_defect`.

12. **Target-incoherent restriction.**  A pre-outcome restriction exists,
    but a carried declared future probe does not preserve the target class.
    Status: `target_incoherent_restriction`.

13. **Clean goal.**  `Theta` selects a target quotient and the selection
    persists across declared route substitutions, with route evaluations
    linked to Delta against that same target quotient.  Status: `goal`.

14. **Route-unstable target.**  `Theta` selects a target quotient and at
    least two carried route alternatives are evaluated against it, but the
    selection does not persist under route substitution.  Status:
    `route_unstable`.

15. **Reward proxy only.**  A scalar reward proxy explains selection, but no
    route-substitution persistence is certified.  Status:
    `reward_proxy_only`.

16. **Uncarried goal/intention package.**  A route-persistent or
    support-restricting object is externally installed or lacks D3
    provenance.  It cannot enter the positive `intention` or `goal` branch;
    depending on the claim, it is a scaffold or rejected status.

17. **Per-claim scoping control.**  A status record for package `C_i` cannot
    classify package `C_j`, even when both are in the same E-system and
    challenge class.  This guards the global-uniqueness bug class fixed in
    E8.

18. **E11 planning/execution compatibility control.**  A planning-layer
    restriction may later be shown to instantiate E11's
    `InstitutionalIntervention`/`MatchedInstitutionalComparison`, but E10.1
    itself classifies intention through the direct FIII support-restriction
    gate.  Status follows the E10.1 apparatus, not E11 status labels.

## 5. Interaction Status

**D3.**  E10 is carried-record-first.  Package, formation, invocation,
kernel-support, channel/status, support-restriction, route-evaluation, and
goal/intention status records are all credited through
`CarriedRecordAt`/`CarriedSource` occurrence data.  Missing provenance is a
first-class `scaffolding` branch, not a side condition.

**D4.**  E10 is a single-`ESystem` law over `S.T`, `S.Lambda_S`, and the
carrier's audit policies.  It introduces no new ledger or repair kernel.
The support/quotient comparators are shared certified inputs over the same
carrier.

**E1.**  E10 uses E1-style Delta vocabulary for the repair conjunct:
nonempty failure before the package and strict reduction after the package.
The draft keeps the `afterQuotientInstalledByPackage` link so the Delta
credit is about the specific package being classified.

**FIII TopDownChannel.**  Direct dependency.  The core difference-making
condition uses `SixBirdsIII.TopDownChannelRecord`,
`TopDownChannelAcceptedBool`, and `TopDownChannelClaimStatus`.  This follows
E4's direct-reuse precedent and does not route through E11.

**E11 forward obligation.**  The order-12 interaction row says that when
E10.1 lands, its planning/execution carriers should be checked against
E11's `InstitutionalIntervention`, `MatchedInstitutionalComparison`, and
D4-grounded support/closure comparators without weakening E11's FIII gate
(`interaction_matrix.md:124`).  This draft addresses that obligation at the
design level: E10.1 keeps the same FIII acceptedness gate and exposes
support-restriction records that a later combined theorem can map into
E11's planning/execution vocabulary.  It does not discharge the theorem-level
bridge to E11, because E10.1 is intentionally a generic internal-package
demarcation and E11 is a within-system layer-rewrite law.

**F25/F31.**  Certified background only.  The causality/counterfactual
discipline named by the source text is represented by the shared
top-down-channel and matched-control inputs; E10 does not mechanize F25 or
F31 locally.

**Agents paper.**  Certified host input for enablement/causation and the
schedule-trap null.  This is newly relevant Agents-paper content for E10:
it is not the same viability-kernel fixed-point input used by E5/E7/E12.

**F19.**  Certified host input for E10.2 route-substitution persistence.
E10.2 does not mechanize F19 object persistence; it requires a carried,
route-linked persistence certificate over the target quotient.

**E3/E4/E5/E6+E9/E7/E8/E12/E13.**  No direct dependency is intended.  E10
shares vocabulary families with several laws (E4 and E11 via FIII, E8 via
anti-correlate/proxy discipline, E13 via decodable-vs-transport controls),
but its theorem surface is the internal package demarcation for one system.

## 6. Nonclaims

1.  E10 does not say passive representation is cognitive.  The decodable
    correlate branch is explicit and load-bearing.

2.  E10 does not classify whole agents.  It imports the Agents
    enablement/causation hinge for internal packages.

3.  E10 does not prove the FIII top-down-channel theorem, F25/F31
    counterfactual discipline, Agents-paper nulls, or F19 persistence.  It
    uses the corresponding certified records as inputs.

4.  E10.1 does not license post-hoc intention as intention.  The timing
    audit is a separate higher-priority branch.

5.  E10.1 does not treat approximate or stochastic support restriction as
    exact intention.  Approximation enters only as a statused defect.

6.  E10.2 does not identify goals with reward scalars, utilities, or
    teleology.  A reward proxy without route-substitution persistence is a
    rejection branch.

7.  E10 does not discharge E11's planning/execution theorem bridge.  It
    keeps the shared FIII gate compatible and records the bridge as a later
    combined-law obligation.

8.  E10 does not classify inter-carrier teaching, communication, or symbols;
    those are E13 transport claims.

9.  E10 does not make a universal empirical claim about every host's
    comparator honesty.  The law is conditional on honest carried records,
    shared comparator policies, and certified host inputs.

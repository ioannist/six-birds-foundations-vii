## 1. Setup

Let

```text
S : ESystem FData RuleFamily ResidualFamily AuditAccessData
      InstrumentRecord LedgerEntry DefectRecord MovePayload MoveRecord AuditRecord
T := S.T   -- TheoryPackage, carrier Z := T.Z
```

be a D4 E-system. E12 does not introduce a parallel carrier. A **subcarrier** is a predicate on the
existing carrier:

```text
def Subcarrier (T : TheoryPackage ...) := T.Z → Prop
```

Individuation is a status assigned to a subcarrier `I : Subcarrier T`, relative to a declared,
certified family of viability probes and a declared scope (both certified host input — see
"Viability probes" below).

**Declared candidate subcarriers (round-2 fix).** Status is only evaluated against a declared, finite
family `Candidates : List (Subcarrier T)` — subcarriers proposed as candidate individuals (legal
entities, subsidiaries, modules), not arbitrary predicates on `T.Z`. This is the same "declared"
discipline already used for the viability-probe family, and matches the source text's own toy-lab
framing ("exhaustive quotient search on the finite carrier"). Without this restriction, `federated`
status (below) would fire for an arbitrary, undeclared fragment of an otherwise-clean integrated
individual, which is not the intended reading of "coalition of siblings." `MaximalIndividuating`,
`OverlapsAnotherMaximal`, and the coalition witness in `FederatedEvidence` all range over `Candidates`,
not over all of `Subcarrier T`.

### Record closure (defined first — repair and budget closure both cite it)

Reuses D3/D4's carried-ledger apparatus directly. Fix `recordPolicyI : CarriedRecordPolicy S.T
LedgerEntry` as `I`'s own restricted record policy (a certified sub-policy of `S`'s ambient policy,
scoped to sources whose carried state lies in `I`):

```text
def EntryClosedOn (I : Subcarrier T) (entry : LedgerEntry) : Prop :=
  entry ∈ S.Lambda_S.ledgerEntries ∧
  (∃ n : Nat, CarriedRecordAt recordPolicyI entry n FineSourceTag.committed_state true true)

def RecordClosedOn (I : Subcarrier T) : Prop :=
  (∃ entry, GeneratedByActivityIn I entry) ∧    -- non-vacuity: genuine ledger activity attributed to I
  ∀ (entry : LedgerEntry), GeneratedByActivityIn I entry → EntryClosedOn I entry
```

i.e. every ledger entry generated by `I`'s own repair/budget activity is carried under `I`'s own
record policy, not requiring an external carrier to close the record. The non-vacuity conjunct blocks
an inert subcarrier with zero recorded activity from trivially satisfying record closure.

### Repair closure

E12 does not define a new repair-generator surface. It reuses D4's raw repair-step relation directly
— **not** E1's `EndogenousRepairOccurrence` (that predicate is scoped to challenge-episode-driven
endogenous repair specifically, a narrower thing than "any repair attributed to `I`"). The right
D4-level anchor is `ESystem.RepairStep`, which already gives an explicit source/successor pair:

```text
structure RepairAttributedTo (I : Subcarrier T) where
  defectRecord : DefectRecord
  auditRecord : AuditRecord
  sourceState : T.Z
  targetState : T.Z
  sourceInI : I sourceState
  isRepairStep : ESystem.RepairStep S sourceState targetState defectRecord auditRecord
  sourceOccurrenceCertified : ... -- CarriedRecordAt-style occurrence, per D3/D4
```

```text
def RepairClosedOn (I : Subcarrier T) : Prop :=
  (∃ r : RepairAttributedTo I, True) ∧   -- non-vacuity: genuine repair activity attributed to I
  ∀ r : RepairAttributedTo I, I r.targetState
```

`r.targetState` is `ESystem.RepairStep`'s own `z'`, so "successor state reached by the repair move" is
now pinned to an existing D4 relation, not deferred.

### Budget closure

E12 reuses E6+E9's already-landed budget apparatus directly, not a new pricing surface. Note
`ExposureBudgetWitness` has no "source/holder" field — it only carries `budgetEntry : LedgerEntry`
and `budgetEntryInLedger : budgetEntry ∈ S.Lambda_S.ledgerEntries`. The correct closure condition is
therefore stated by reusing `EntryClosedOn` (defined just above) wholesale on the witness's own
`budgetEntry`, exactly the same way E11's `ConstitutiveEvidenceExistsFor` reused
`ConstitutiveEvidence` wholesale rather than re-deriving a weaker, ad hoc condition:

```text
def BudgetClosedOn (I : Subcarrier T) : Prop :=
  (∃ (economy : ProbeEconomy S Probe XiFamily) (move : ProbeMove Probe XiFamily)
     (w : ExposureBudgetWitness economy move),
    BudgetFeasible w ∧ AttributedToI I w) ∧   -- non-vacuity: a genuine FEASIBLE witness attributed to I
  ∀ (economy : ProbeEconomy S Probe XiFamily) (move : ProbeMove Probe XiFamily)
    (w : ExposureBudgetWitness economy move),
    BudgetFeasible w →
    AttributedToI I w →   -- the access move's spend is attributed to activity within I
    EntryClosedOn I w.budgetEntry   -- the funding ledger entry is itself record-closed on I
```

**Round-2 fix:** the type shape is now `ExposureBudgetWitness economy move` (matching
`E6E9PricedAccess.lean:46-65` exactly — not the round-1 draft's invented `probe xi` indexing), and the
non-vacuity witness now explicitly requires `BudgetFeasible w`, not just attribution. Without that
conjunct, an attributed but *infeasible* witness could satisfy non-vacuity while the universal
implication (which is itself gated on `BudgetFeasible w`) remained vacuously true for every feasible
witness — the round-1 fix closed one vacuity path but left this one open.

`AttributedToI` mirrors `RepairAttributedTo`'s attribution pattern: an access move is attributed to
`I` when its selecting `AccessPolicy` occurrence's carried source state lies in `I`. Budget closure
fails (the "subsidized bureau" case from the source text) exactly when some feasible, attributed
access move's `budgetEntry` fails `EntryClosedOn I` — i.e. the funding entry is carried outside `I`'s
own record policy.

### Viability probes and the boundary

A declared, certified family of viability probes `{v_i}` (Agents-paper viability-kernel readouts,
certified host input — not re-derived here) targets the interface between `I` and its complement. The
**boundary** `B(I)` is a quotient of that interface:

```text
structure InstitutionalBoundaryCandidate (I : Subcarrier T) where
  interfaceQuotient : InterfaceState I → BoundaryQuotient
  ...
```

`B(I)` is **viability-sufficient** iff every declared probe `v_i` descends through `interfaceQuotient`
**and** `interfaceQuotient` is the *coarsest* quotient with that property — F7 sufficiency plus F10
coarsest-quotient content applied to the viability-probe family, both certified host input (dropping
the coarsestness conjunct would silently weaken the source text's own boundary condition, THEOREMS.md
line 347, "the coarsest quotient... through which all declared viability probes descend"):

```text
def ViabilitySufficientBoundary (I : Subcarrier T) (B : InstitutionalBoundaryCandidate I) : Prop :=
  SufficiencyClosureCertified viabilityProbes B.interfaceQuotient ∧      -- certified F7 input
  CoarsestQuotientCertified viabilityProbes B.interfaceQuotient          -- certified F10 input
```

**Round-2 fix (factorization direction):** "`q` factors through `π`" (`∃f, q = f ∘ π`) means `q` is
computable from `π` alone, i.e. `π` is at least as fine as `q`, i.e. `q` is coarser-or-equal to `π`.
For `B.interfaceQuotient` to be the *coarsest* sufficient quotient, it must therefore factor through
*every other* sufficient `π` — the round-1 draft had this backwards (it required `π` to factor through
`B.interfaceQuotient`, which would certify `B.interfaceQuotient` as the *finest*, not coarsest,
sufficient quotient):

```text
def CoarsestQuotientCertified (viabilityProbes) (q : InterfaceState I → BoundaryQuotient) : Prop :=
  ∀ (Q' : Type) (π : InterfaceState I → Q'), SufficiencyClosureCertified viabilityProbes π →
    ∃ f : Q' → BoundaryQuotient, q = f ∘ π
```

`B(I)` is **self-maintained** iff its own apparatus is a genuine `ClosureApparatus` (direct reuse of
E3's landed machinery, not a certified bridge) satisfying `MaintenanceReinstatementFor` under
challenge:

`MaintenanceReinstatementFor`'s actual signature (`E3SelfMaintainingReclosure.lean:133-174`) takes
concrete witnesses `t : Nat`, `app_t app_tplus1 : ClosureApparatus S`, `m : ClosureMaintenanceOperator
S`, and `record : MaintenanceReinstatementRecord S` — not an abstract "challenge" argument (the
round-1 draft's `∀ challenge, ... app challenge` did not type-check against this). `record` already
carries its own `sourceState : S.T.Z` field (per `MaintenanceReinstatementRecord`'s fields), which is
exactly the existing anchor for "maintained by `I` itself" — no new attribution machinery needed,
reusing the same pattern as `RepairAttributedTo`:

```text
def SelfMaintainedBoundary (I : Subcarrier T) (B : InstitutionalBoundaryCandidate I) : Prop :=
  ∃ (t : Nat) (app_t app_tplus1 : ClosureApparatus S) (m : ClosureMaintenanceOperator S)
    (record : MaintenanceReinstatementRecord S),
    BoundaryApparatusFor B app_t ∧
    MaintenanceReinstatementFor S H appPolicy maintenancePolicy reinstatementPolicy
      t app_t app_tplus1 m record ∧
    I record.sourceState   -- maintained BY I itself: the reinstatement's own carried source state lies in I
```

The last conjunct — "maintained by `I` itself" — is the load-bearing distinction between `integrated`
and `platform_dependent` status below: `record.sourceState` (the reinstatement's own carried source
state, per E3's existing structure) must lie in `I`, not in some external carrier. Persistence across
repeated challenges reuses E3's own `ClosureApparatusChallengeAt` wrapper rather than inventing a
fresh universal quantifier.

### Maximality

```text
def Individuates (I : Subcarrier T) : Prop :=
  RepairClosedOn I ∧ BudgetClosedOn I ∧ RecordClosedOn I ∧
  (∃ B, ViabilitySufficientBoundary I B ∧ SelfMaintainedBoundary I B)

def MaximalIndividuating (I : Subcarrier T) : Prop :=
  I ∈ Candidates ∧ Individuates I ∧
  ∀ I' ∈ Candidates, I ⊆ I' → Individuates I' → I' = I  -- no strictly larger closing candidate
```

### Status apparatus (six-way)

```text
inductive IndividuationStatus where
  | integrated
  | federated
  | subsidiary
  | platform_dependent
  | shadow
  | non_individuated
```

The source text's own gloss (THEOREMS.md line 349) reads federated as "joint closure only at
coalition level" — `I` alone does not close; a coalition does. Its obstruction note (line 353) adds a
second, distinct signal: "overlapping maximal closures classify as federated" — two *different*
maximal-individuating subcarriers that share members (neither contains the other) should both read as
federated rather than both claiming `integrated`. Both signals are genuine and are folded into one
predicate below, rather than silently dropping the second (a review-round-1 fix, replacing the first
draft's single-signal definition, which conflated "fails maximality alone" with "coalition-only
closure" and did not handle the overlap case at all):

```text
def OverlapsAnotherMaximal (I : Subcarrier T) : Prop :=
  ∃ I' ∈ Candidates, MaximalIndividuating I' ∧ I' ≠ I ∧
    (∃ z, I z ∧ I' z) ∧ ¬ (I ⊆ I') ∧ ¬ (I' ⊆ I)

def FederatedEvidence (I : Subcarrier T) : Prop :=
  (I ∈ Candidates ∧ ¬ Individuates I ∧
    ∃ C ∈ Candidates, I ⊆ C ∧ I ≠ C ∧ MaximalIndividuating C) ∨
  (MaximalIndividuating I ∧ OverlapsAnotherMaximal I)
```

Restricting `C`/`I'` to `Candidates` is what makes "coalition-only closure" mean something: an
arbitrary undeclared fragment of an already-integrated `I` is never itself a member of `Candidates`,
so it is never even eligible to be checked for `FederatedEvidence` in the first place. Only genuinely
declared sibling entities (and genuinely declared coalitions of them) can satisfy the coalition
disjunct — this is the round-2 fix for the "arbitrary subpart of an integrated individual" gap.

**External-review-gate addendum (v22 CHANGE-REQUEST fix):** the round-2 fix above closes the gap for
`MaximalIndividuating`/`OverlapsAnotherMaximal`/`FederatedEvidence`, but external review v22 found it
was not threaded into the status-certification surface itself — `IndividuationStatusOccurrenceFor` (and
therefore every `...Holds` predicate and both theorems) took no candidate-membership hypothesis at all,
so an undeclared subcarrier could in principle still be certified with a status if a host supplied a
fully carried, well-formed status record for it. The fix adds `I ∈ candidates.members` as
`IndividuationStatusOccurrenceFor`'s own first conjunct, closing candidate-eligibility at the one choke
point every status certification must pass through.

The six case predicates are then **priority-normalized**: each explicitly excludes every
higher-priority case, in the source text's own listing order (integrated > federated > subsidiary >
platform_dependent > shadow > non_individuated) — the same discipline E1's five-way
`InternalizationStatus` and E3's four-way `MaintenanceClosureStatus` each already use for their own
partially-overlapping evidence predicates:

```text
def IntegratedCase (I : Subcarrier T) : Prop :=
  MaximalIndividuating I ∧ ¬ OverlapsAnotherMaximal I

def FederatedCase (I : Subcarrier T) : Prop :=
  ¬ IntegratedCase I ∧ FederatedEvidence I

def SubsidiaryCase (I : Subcarrier T) : Prop :=
  ¬ IntegratedCase I ∧ ¬ FederatedCase I ∧
  RepairClosedOn I ∧ RecordClosedOn I ∧ ¬ BudgetClosedOn I ∧
  (∃ B, ViabilitySufficientBoundary I B)   -- boundary still identifiable, budget external

def PlatformDependentCase (I : Subcarrier T) : Prop :=
  ¬ IntegratedCase I ∧ ¬ FederatedCase I ∧ ¬ SubsidiaryCase I ∧
  RepairClosedOn I ∧ BudgetClosedOn I ∧ RecordClosedOn I ∧
  (∃ B, ViabilitySufficientBoundary I B ∧ ¬ SelfMaintainedBoundary I B)

def ShadowCase (I : Subcarrier T) : Prop :=
  ¬ IntegratedCase I ∧ ¬ FederatedCase I ∧ ¬ SubsidiaryCase I ∧ ¬ PlatformDependentCase I ∧
  RepairClosedOn I ∧ BudgetClosedOn I ∧ ¬ RecordClosedOn I

def NonIndividuatedCase (I : Subcarrier T) : Prop :=
  ¬ IntegratedCase I ∧ ¬ FederatedCase I ∧ ¬ SubsidiaryCase I ∧
  ¬ PlatformDependentCase I ∧ ¬ ShadowCase I
```

`NonIndividuatedCase` is defined purely as the negation of the other five, by construction — not by
an independent "no boundary candidate exists" clause. This closes the review-round-1 gap where a
subcarrier with a fine boundary but failing *all three* closures (repair, budget, and record) had no
case to land in: it now correctly falls through to `NonIndividuatedCase`. Because each later
predicate explicitly negates every earlier one, the six cases are pairwise exclusive by construction,
and their disjunction is exhaustive by `NonIndividuatedCase`'s own definition — the partition no
longer depends on an unstated assumption that the underlying evidence happens not to overlap.

## 2. Theorem

**`E12_Individuation`** (name pending review): under the certified viability-probe family and
certified F7/F10/F17/F19 host inputs, if `I` carries a status-record witnessing one of
`IntegratedCase`/`FederatedCase`/`SubsidiaryCase`/`PlatformDependentCase`/`ShadowCase`/
`NonIndividuatedCase` with all constituent carried-occurrence and audit conditions certified, then
`I`'s `IndividuationStatus` is exactly that case. Because each case predicate explicitly negates every
higher-priority case (§1), no other case can hold for `I` simultaneously — this is now a direct
consequence of the definitions, not a separately-argued fact.

**`E12_StatusPartition`**: given an occurrence-complete status classifier for `I` (a carried
`IndividuationStatusRecord` witnessing one branch with all supporting ledger/audit evidence
certified), exactly one of `IntegratedCase`/`FederatedCase`/`SubsidiaryCase`/`PlatformDependentCase`/
`ShadowCase`/`NonIndividuatedCase` holds for `I` — exclusivity from the priority-normalization above,
exhaustiveness from `NonIndividuatedCase`'s catch-all definition.

### Obstruction/falsifier set

For each claimed individual `I`, exhibit one of:

- **`Δ_bound`**: a declared viability probe `v_i` that does not descend through `B(I).interfaceQuotient`
  (boundary too coarse — `ViabilitySufficientBoundary` fails).
- **`Δ_flow`**: a repair, budget, or record flow crossing `B(I)` without a carried interface record
  (closure violated — one of `RepairClosedOn`/`BudgetClosedOn`/`RecordClosedOn` fails for a witnessed
  flow).
- **`Δ_max`**: a strictly larger subcarrier `I' ⊋ I` with the same three closures and the same
  viability-sufficient self-maintained boundary status (maximality violated).

Non-uniqueness of maximal closures is explicitly **not** treated as a falsifier — it is absorbed by
the `federated` branch, per the source text.

## 3. Proof Spine

1. Fix `S : ESystem ...` and a candidate subcarrier `I : Subcarrier T`.
2. Establish `RecordClosedOn I` from `S.Lambda_S`'s carried ledger entries attributed to `I`, with a
   genuine witnessed-activity conjunct — direct D3/D4 reuse, defined first since repair/budget closure
   both cite `EntryClosedOn` wholesale.
3. Establish `RepairClosedOn I` from carried `RepairAttributedTo I` occurrences pinned to D4's own
   `ESystem.RepairStep S z z' defect auditRecord` relation (not E1's episode-tied
   `EndogenousRepairOccurrence`, which is scoped to challenge-driven repair specifically), with a
   genuine witnessed-activity conjunct.
4. Establish `BudgetClosedOn I` from carried `ExposureBudgetWitness`/`BudgetFeasible` occurrences
   attributed to `I`, requiring each witness's `budgetEntry` to satisfy `EntryClosedOn I` (reusing step
   2's predicate wholesale, not a separate "source/holder" notion `ExposureBudgetWitness` does not
   carry) — direct E6+E9 reuse, plus a genuine witnessed-activity conjunct.
5. Fix a boundary candidate `B` for `I` and certify `ViabilitySufficientBoundary I B` via the
   certified F7 (sufficiency) *and* F10 (coarsest-quotient) host predicates jointly over the declared
   viability-probe family — both conjuncts required, not sufficiency alone.
6. Certify `SelfMaintainedBoundary I B` via direct reuse of E3's `ClosureApparatus` and
   `MaintenanceReinstatementFor`, checking the reinstatement operator is itself attributed to `I` (not
   an external carrier) — this attribution check is the anti-unlinked-evidence guard analogous to
   E3's own operator/state/apparatus linkage and E11's channel/effect/comparison linkage.
7. Derive `MaximalIndividuating I` and `OverlapsAnotherMaximal I` from steps 2-6 plus an exhaustive
   quotient search over candidate supersets/siblings on the finite carrier (toy-lab side; the Lean
   theorem takes maximality/overlap as carried hypotheses, per the verification-shaped house style).
8. Evaluate `IntegratedCase`/`FederatedCase`/`SubsidiaryCase`/`PlatformDependentCase`/`ShadowCase`/
   `NonIndividuatedCase` in priority order (§1) — each later predicate's explicit negation of every
   earlier one is what makes the case split well-defined, not an assumption that the underlying
   evidence happens not to overlap.
9. For the `FederatedCase` branch specifically, exhibit either (a) a genuine coalition `C ⊋ I` with
   `MaximalIndividuating C`, distinguishing this from a vacuous `C = I` case, or (b) a genuine distinct
   overlapping `MaximalIndividuating I'` witness — both disjuncts of `FederatedEvidence` need their own
   non-vacuous witness, following the standing "check the fix doesn't reintroduce vacuity" discipline
   from E3/E11's own landing.
10. Derive `E12_StatusPartition` from `NonIndividuatedCase`'s catch-all definition (exhaustiveness) and
    the priority-normalization's explicit negations (pairwise exclusivity) — both now definitional, in
    the same style as `E1_StatusPartition`/`E3_StatusPartition`.
11. State the obstruction/falsifier set as the direct contrapositives of steps 3-4 (`Δ_flow`), step 5
    (`Δ_bound`), and `MaximalIndividuating`'s own universal clause (`Δ_max`).

## 4. Case Enumeration

1. `IntegratedCase`: `MaximalIndividuating I` and no distinct overlapping maximal subcarrier — the
   clean standalone-firm/self case.
2. `FederatedCase`, coalition-only disjunct: `I` alone fails to individuate, but a genuine coalition
   `C ⊋ I` does — the consolidation-accounting recognized instance.
3. `FederatedCase`, overlap disjunct: `I` is itself `MaximalIndividuating`, but shares members with a
   distinct `MaximalIndividuating I'` (neither contains the other) — the joint-venture/shared-resource
   recognized instance, absorbing non-uniqueness per the source text.
4. `SubsidiaryCase`: repair and record closed, budget external, boundary still identifiable — the
   subsidized-bureau recognized instance.
5. `PlatformDependentCase`: all three closures hold, boundary viability-sufficient, but maintained by
   another carrier — the platform/DAO-hosted-entity recognized instance.
6. `ShadowCase`: repair and budget closed, records closed elsewhere — an entity whose own bookkeeping
   is externally carried.
7. `NonIndividuatedCase`: none of the above five — includes both "no boundary candidate at all" and
   the previously-unhandled case of a fine boundary with repair/budget/record closure failing in a
   combination none of cases 4-6 name (e.g. record closed but both repair and budget external).
8. Edge case: `I = ∅` (empty subcarrier) — must fail every closure predicate's non-vacuity conjunct,
   landing in `NonIndividuatedCase`, not vacuously satisfy closure.
9. Edge case: `I` = the whole carrier `T.Z` — must still pass a genuine `MaximalIndividuating` check
   (no strictly larger subcarrier exists trivially, since none can), not be special-cased separately.
10. Edge case: a claimed `FederatedCase` coalition `C` with `C = I` — must be rejected by
    `FederatedEvidence`'s own `I ≠ C` conjunct, not silently accepted as coalition-level closure.
11. Edge case: a boundary candidate `B` that is self-maintained but by an operator whose attribution to
    `I` is itself uncertified — must fail `SelfMaintainedBoundary`, not default to `PlatformDependentCase`
    by omission.
12. Edge case (falsifier `Δ_max`): a strictly larger subcarrier exists that closes identically —
    `I` must not be classified `IntegratedCase`/`FederatedCase` in this case (blocked by
    `MaximalIndividuating`'s own universal clause).
13. Edge case (falsifier `Δ_flow`): a repair or budget move whose source lies in `I` but whose
    successor/funding entry lies outside `I` with no carried interface record — closure genuinely
    fails, must not be masked by an uncertified/absent occurrence check.
14. Edge case: two distinct candidates `I`, `I'` each satisfying `IntegratedCase` in isolation because
    the `OverlapsAnotherMaximal` check was run against the wrong carrier's occurrence list — must be
    checked against the *same* `S`'s full subcarrier space, not a locally-scoped subset (an
    anti-unlinked-evidence concern analogous to E11's own comparison-wide vs. per-witness bug).

# G12 Gate And Null-Battery Record

**Unit:** G12 - Finite Witness Radiation
**Kind:** Theorem / finite-witness restriction and orbit radiation, with a compactness-bridge completion
schema and a real literature-sourced calibration exhibit
**Recorded:** 2026-07-07

G12's Lean file proves a genuinely unconditional finite-witness restriction theorem and orbit-radiation
theorem, plus a compactness-bridge completion result conditional on a named, unproved hypothesis. The
landed declarations used for this panel are: `ProperKColoring`, `FiniteWitnessObstruction`,
`no_global_k_coloring`, `StructurePreserving`, `orbit_radiation`, `CompactnessBridge`, and
`finite_witness_iff_no_global_coloring`. **This is the thirteenth and final law landed in the whole
Foundations VI program.** Euclidean geometry, the isometry group, unit-distance coordinates, SAT/DIMACS
proof certificates, and the de Bruijn-Erdos compactness theorem itself are explicitly imported instance
content, not reproduced in Lean.

Fresh axiom reports were run against the top-level G12 theorem declarations for this packet:

```text
'SixBirdsFoundationsVI.Laws.G12FiniteWitnessRadiation.no_global_k_coloring' does not depend on any axioms
'SixBirdsFoundationsVI.Laws.G12FiniteWitnessRadiation.orbit_radiation' does not depend on any axioms
'SixBirdsFoundationsVI.Laws.G12FiniteWitnessRadiation.finite_witness_iff_no_global_coloring' does not depend on any axioms
```

All three are fully axiom-free — not even `propext`, unlike most prior laws in this catalog.

The vendored `SixBirdsIII.Promotion` module supplies the nine gate fields and status vocabulary:
`GateStatus.pass`, `GateStatus.notRequired`, `GateStatus.outsideScope`, and the corresponding
`StrictGateStatus` constructors for the strict gate. G12 is not packaged as one `PromotionBridgeData`
value, so this panel is scored manually against the landed Lean declarations and lab artifacts, following
the same convention used by all twelve prior gate files.

Scope note: G12-L1 verifies a real, literature-sourced 826-vertex unit-distance graph (the
Heule/Polymath16 intermediate construction vendored from `cs.utexas.edu/~marijn/CNP/826.{vtx,edge}` — see
`lab/foundations_vi_lab/g12_finite_witness/data/PROVENANCE.md`) end-to-end: exact algebraic-arithmetic
unit-distance verification for all `4273` declared edges (two independent methods: pure symbolic
simplification and 60-digit-precision numeric cross-check, both zero failures; `2000` random sampled
non-edges confirmed not accidentally at unit distance), and non-4-colorability via a real SAT solve on the
standard 4-coloring CNF encoding (`3304` variables, `22874` clauses). The manager independently
reconstructed the identical CNF from scratch and confirmed it is byte-for-byte identical as a clause SET
to the committed file, then independently solved it with two different solvers (`Glucose3`: UNSAT in
`629.10s`; `Kissat404`: UNSAT in `308.38s`), agreeing with Coder's own third, independent run
(`kissat404`, UNSAT, `533.18s` on the identical clause set). This is NOT the smallest known 5-chromatic
unit-distance graph (Parts's 509-vertex record, arXiv:2010.12665) — Parts's own raw coordinates were not
found publicly archived. **Correction (2026-07-07, external review):** the original choice of `826` was
justified by a literature-verification pass that also (incorrectly) concluded no smaller Heule/Polymath
graph had public coordinate-plus-edge data either; that pass missed Heule's own `github.com/marijnheule/
CNP-SAT` repository, which publicly hosts matched `.vtx`/`.edge` data for `510`/`517`/`529`/`553`/`610`/
`633`/`803` as well — all smaller than `826` and equally well-documented. `826` is therefore not "the
smallest well-documented graph," just a valid one that happened to already be vendored. The UNSAT
determination for this specific `826` instance is solver-verified, not independently proof-checked,
because `826` has no DRAT certificate in that repository — but `517`/`529`/`553`/`610`/`633`/`803` DO have
public DRAT certificates there, so the earlier claim that none exists "for any graph in this literature
stream" was also wrong. See `data/PROVENANCE.md` for the full correction.

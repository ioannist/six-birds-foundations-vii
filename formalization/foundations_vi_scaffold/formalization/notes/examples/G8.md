This note is the six-part deep-dive split out from `THEOREMS.md`'s compressed G8 catalog entry, per

## 1. Setup → Lean target

`THEOREMS.md` §G8 "1. Setup" (configuration space `C`, sites `V`, partial local moves `m_v`, legality
`L_v`, runs, counter vectors, stability, sufficiency, plus the boxed hypotheses `[H-G8]` and
`[H-G8-mono]`) is mechanized in `lean/SixBirdsFoundationsVI/Laws/G8OdometerAbelianization.lean` as:
`ApplyRun`, `LegalRun` (inductive relation over finite `List V` runs), `RunCounter`/`HasCounter`,
`Stable`, `Sufficient`, `Necessary`, `PointwiseLE`/`PrefixBoundedBy`, `AbelianCompatible` (`[H-G8]`),
`LeastActionMonotonicity` (`[H-G8-mono]`), and `Steps`/`TerminatesFrom` (Lean-core `Acc`-based
termination, the Mathlib-free rendering of "every maximal legal run from `x` terminates"). `C` and `V`
are left as arbitrary `Type`s (only `DecidableEq V` added, for counter comparison) — no finiteness
typeclass is imposed, matching this project's established pattern elsewhere (e.g. F4's
`LocalGlobalObstruction.lean`).

**No Lean imports.** G8's file is fully standalone (`grep '^import'` returns nothing) — its "Closest
Foundations IV cousins" (F3, F27) are prose-level differentiation, not a Lean dependency; G8 does not
build on F3's/F27's mechanized statements.

## 4. Case enumeration → Lean target (local examples)

- **Case (b)** (confluent without canonical counters): `CaseBState`/`CaseBMove` (4 states, 5 moves),
  `caseBMove`/`caseBLegal`. Proves `caseB_not_abelian` (`[H-G8]` genuinely fails: firing `r` kills `s`'s
  legality), `caseB_stable_run_from_S_ends_N` (general confluence — *every* stable legal run from `S`
  ends at `N`, not just the three displayed routes), `caseB_terminates_from_S` (`Acc`-based termination,
  built bottom-up from `N`), and `caseB_route_dependent_counter` (`[r,p]` fires `s` zero times, `[s,q]`
  fires it once).
- **Case (d)** (terminating, non-confluent): `CaseDState`/`CaseDMove` (3 states, 2 moves). Proves
  `caseD_nonconfluent_witness`: both one-step routes from `S` are legal and stable, reaching distinct
  final states `A ≠ B`.
- **Local example (G8-L2)**: `lab/foundations_vi_lab/g08_odometer/case_b.py` reuses the *exact same*
  concrete case (b) system (same states/moves/transitions/legality), not an independent rewrite system —
  this gives an exact cross-check between the Lean proof and a computational sweep (1000 seeded random
  orders, seed 8602, all reaching `N` with 3 distinct counter vectors observed).
- **Local example (G8-L1)**: `lab/foundations_vi_lab/g08_odometer/sandpile.py`, exact-integer 4-neighbor
  grid sandpile with boundary sink, grids 10×10 through 50×50, 500 seeded random legal stabilizations
  (seed 8601) all agreeing exactly with deterministic min/max-choice baselines on final configuration and
  odometer — a direct computational instance of Part A.

## 7. Prose-to-Lean fidelity issues found during mechanization (all resolved)

Recorded honestly per `design/06_FORMALIZATION.md`'s discipline — these are exactly the kind of gaps the
Lean gate is supposed to catch that prose-only review missed:

1. **`[H-G8-mono]` was initially vacuous.** The first encoding of `LeastActionMonotonicity` had a
   conclusion that followed from pure arithmetic on `scriptLe` alone, never actually using `Sufficient` or
   a `necessary` predicate — Reviewer caught this on the first Lean-subsection-1 review pass. Fixed by
   redesigning it as a genuine exchange/domination hypothesis on legal-run prefixes
   (`LegalRun`/`Sufficient`/`PrefixBoundedBy`/exact-exhaustion → `False`), confirmed non-vacuous by
   construction (falsifying it requires real facts about `L`, not just counting).
2. **`AbelianCompatible` had a redundant guard** (logically equivalent but harder to use) — simplified.
3. **`least_action` initially omitted the standing `[H-G8]` hypothesis** from the prose's Theorem-section
   header, even though the proof turned out not to need it (since the fixed `LeastActionMonotonicity`
   already packages the needed content) — fixed by adding `_habelian : AbelianCompatible m L` as an
   explicit (unused-in-proof) hypothesis, for statement fidelity to the prose's stated scope, matching
   Part A's precedent for `_hterminates`.
4. **Case (b)'s first draft only checked 3 specific routes**, not general confluence/termination for the
   whole system — fixed by adding `caseB_stable_run_from_S_ends_N` (exhaustive case analysis) and
   `caseB_terminates_from_S` (explicit bottom-up `Acc` construction).
5. **G8-L1's lab verdict initially omitted** that the design spec's least-action/wasteful-stabilization
   sub-experiment (needing a citable Fey-Levine-Peres construction) was out of scope for the packet that
   ran — fixed by adding an explicit "Open Item" section to both the verdict and its generator function
   (the first fix touched only the checked-in file, missing that the generator would silently regenerate
   it without the disclosure — caught on a second Reviewer pass).
6. **`least_action` was described too broadly relative to the Lean predicate `Sufficient`.** The Lean
   predicate requires an actual `LegalRun`, so the theorem compares the legal odometer only with other
   legally sufficient scripts. This is a sound and useful Part B theorem, but it is narrower than the full
   Fey-Levine-Peres comparison against arbitrary nonnegative force-firing scripts with illegal
   intermediate topplings. Fixed by narrowing `THEOREMS.md`, this note, the gate panel, and the Lean
   doc-comments; no proof term was changed.

None of these fixes weakened the law's actual mathematical content — the first five were either vacuity/rigor
fixes (1, 4) that made the mechanization strictly *more* checking than the first draft, fidelity/framing
fixes (2, 3) with zero semantic change, or honesty-of-disclosure fixes (5) with zero change to what was
actually run. Item 6 is a scope correction: it records that the shipped theorem is the legal-vs-legal
least-action result actually proved, not the broader force-firing principle.

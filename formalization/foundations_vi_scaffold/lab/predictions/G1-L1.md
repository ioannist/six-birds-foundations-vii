# G1-L1 Prediction - Collatz Affine Ledger Audit

## Hypothesis
For every tested odd native integer `n`, the accelerated Collatz orbit satisfies
the exact affine ledger identity
`n_k = (3^k*n + B_k) / 2^A_k` at every checked horizon up to first descent,
with `A_k = sum_{j<k} a_j`, `a_j = nu_2(3*n_j + 1)`, `B_0 = 0`, and
`B_{j+1} = 3*B_j + 2^A_j`. The descent certificate also satisfies the exact
integer equivalence
`n_k < n <=> 2^A_k*n > 3^k*n + B_k`.

## Predicted Outcome
The sweep over odd `n < 10^6` uses Python arbitrary-precision integers only.
Every ledger numerator is exactly divisible by `2^A_k`, every ledger value
matches direct accelerated iteration, and the descent-boundary equivalence
matches direct comparison at every checked horizon. No floats, approximate
valuation, or rational division are used.

## Falsification Condition
Any odd `n < 10^6` where the tracked `(a_j, A_k, B_k)` ledger disagrees with
direct iteration, where the ledger division has a nonzero remainder, or where
`(n_k < n)` differs from `(2^A_k*n > 3^k*n + B_k)` falsifies this calibration.
Per `design/04_LABS.md`, such a failure would be a genuine formula bug in the
paper-facing G1 setup and must be reported prominently.

# G6-L1 Prediction - Recaman Census

## Hypothesis

The exact Recaman recurrence

```text
a_0 = 0
a_n = a_{n-1} - n  if a_{n-1} - n is positive and unused
a_n = a_{n-1} + n  otherwise
```

run to `10^7` steps will produce high but incomplete coverage in low finite
windows. A nonzero fraction of steps should have a legal backward move. The
smallest missing positive integer may settle for long stretches or continue
climbing within the tested range; the run will report whichever behavior is
actually observed.

## Predicted Outcome

All arithmetic and membership checks are exact. The implementation will use a
bytearray-backed visited set over a declared low range and a Python set for
values above that range if any are reached. No probabilistic membership
structure and no floating-point arithmetic is used for the recurrence or
reported ratios.

The output should include coverage counts for fixed windows, the
smallest-missing trajectory at checkpoints, and the return-pressure proxy
`backward_legal_steps / total_steps`.

## Falsification Condition

Any arithmetic error in the recurrence, especially a mismatch with the
well-known OEIS A005132 prefix, falsifies this exhibit. This lab is a bounded
census only; it is not a proof that Recaman's sequence covers every positive
integer and is not a permanent-hole certificate.
